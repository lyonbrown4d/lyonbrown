# Migration Progress

> Resumed on: 2026-10-05
>
> Development now continues directly on `main`. This page records verified
> engineering state and does not claim that the product is release-ready.

## Integrated on `main`

- Node.js 24, pinned pnpm, strict ESM, repository gates, and bilingual
  VitePress documentation.
- TypeScript domain, protocol/gRPC, authenticated client, launch coordinator,
  durable Runtime adapter, Pi kernel adapter, SQLite EventStore, local control
  plane, Windows native path verification, and local-model foundation.
- The Node TUI replaces the former Rust `apps/agent-cli` implementation and
  pins `@earendil-works/pi-tui@1.0.0`.
- The TUI opens chat by default and includes immediate connection state,
  snapshot revision fencing, English and Simplified Chinese, six themes, model
  setup, approvals, command palette, Activity Inspector, and terminal text
  safety.
- GUI/Desktop code, root Cargo metadata, Rust crates/providers, Rust build
  scripts, and the final Rust TUI snapshot are removed. The tracked repository
  contains no `.rs`, `Cargo.toml`, or `Cargo.lock` product files.
- Windows native model storage now covers private ACLs, reparse-point and file
  identity checks, install locking, bounded staging, atomic activation, and
  installed-file anchoring.
- The staging contract supports the real ipull lifecycle: download to
  `filename.ipull`, rename to the final staged filename, securely re-anchor the
  result, and remove fixed-name residue after a failed download.
- Protocol `.proto` schemas and versioned wire fixtures remain tracked contract
  sources. Generated TypeScript/gRPC files are Git-ignored and regenerated by
  package lifecycle hooks before lint, typecheck, test, and build.
- Authenticated loopback gRPC channels explicitly disable environment HTTP
  proxy discovery, so local daemon traffic cannot be redirected to a proxy.

## Current product state

The repository is Node.js/TypeScript-only, but the product is not yet an
end-to-end runnable checkpoint. Production still needs:

- concrete native discovery, process-spawn, and authenticated client adapters
  for the TUI launcher;
- the complete `agentd` production composition root, descriptor publication,
  ownership-aware shutdown, and executable entry point;
- an authenticated local daemon/TUI end-to-end test;
- complete tools, MCP, approval execution, context, secrets, configuration,
  packaging, and release verification.

The architecture remains singular: `agentd` owns Runtime, models, tools, MCP,
and EventStore; the TUI is only an authenticated gRPC presentation client. No
embedded Runtime, GUI fallback, or Rust compatibility path may be added.
