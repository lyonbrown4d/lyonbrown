# 计划、上下文与变更

agentd 持有计划、运行模式、上下文和变更记录。TUI 与 Desktop 通过认证协议查看和操作；界面状态或模型建议不能授予工具、模型和节点权限。

本文对应当前代码。默认 feature 的工作区已通过编译；测试及界面运行验收未重新执行，现有截图不作为这些入口的验收证据。

## 控制上下文

TUI 使用 `/context` 查看消息数、压缩次数、修订号和输入 token 估算，`/context summary` 单独读取摘要，`/compact [关注点]` 请求压缩，`/context undo` 撤销最近一次压缩。Desktop 的 Runtime status 页面提供对应按钮。

压缩复用 Rig Memory 的 `CompactionPolicy`、`Summarizer`、日志和 `undo_summary`。原始任务单独保留，系统指令保持在运行配置中；摘要只是上下文材料，不能成为授权指令。估算来自框架启发式算法，不是模型服务计费数据；未打开 Runtime 的静态检查不含工具 schema，输出预留单独显示。

自动压缩只发生在下一次模型请求之前的安全边界，不跨越未完成的工具调用。手动压缩和撤销要求当前会话无活动或结果未知的 Run，并核对 `owner_epoch` 与上下文修订。摘要使用当前选定模型，不开放工具调用，受取消、超时和输出大小限制。摘要输入和输出始终经过 Runtime 的共享隐私处理；可选宿主 guard 只能增加限制，不能绕过该边界。摘要请求意图先持久化；无法确认的请求保留原上下文并进入待核对状态，不自动重发。

手动压缩先提交持久维护作业，再释放全局任务准入锁并后台执行。`ContextStatus.maintenance` 返回作业 ID、会话、审计 Run、修订和状态；原 Run 不会重新执行。若请求结果未知，先刷新作业状态；不自动重发 `/compact`。`GetContextMaintenance` 可独立读取作业元数据，不要求模型已加载。`Preparing`、`Sending` 和 `Uncertain` 阻止同一会话启动新 Run、修改模式、转移所有权或执行人工变更；其他会话仍可准入。正在维护的作业计入停机等待与升级检查。当前 daemon 未装配摘要隐私处理时仍拒绝发送摘要，维护作业不会绕过这一限制。

TUI 使用 `/context cancel JOB_ID` 请求取消；Desktop 提供 Cancel。`CancelContext` 针对作业 ID 和所有权版本请求取消。尚未发送的请求清理未发送意图后进入 `Cancelled`；发送后结果不明的请求进入 `Uncertain`。重启只清理未发送准备，不继续发送已存在的摘要请求。取消不能证明远端未处理请求，也不能解决未知结果。

核对后，TUI 使用 `/context abandon JOB_ID REQUEST_UUID REASON`，Desktop 使用 Close uncertain session without replay，明确放弃旧会话的未知上下文。对应 `AbandonContext` 只记录人工放弃，不恢复该会话。该操作要求无活动 Run，并携带稳定请求 UUID、所有权版本和说明；它在同一事务记录审计、递增 `owner_epoch` 并将作业标为 `Abandoned`。原快照和发送意图保留，旧会话永久拒绝新 Run；用户须新建会话继续。已放弃作业不再阻止升级。该操作不会清除发送标记、重发请求或把未知结果当作成功。

## 选择会话模式

`/mode` 列出模式与工具元数据；`/mode read-only`、`/mode plan`、`/mode execute` 切换模式。Desktop 的 Runtime status 页面提供相同选择。

| 模式 | 限制 |
| --- | --- |
| `read-only` | 允许文件、计划、检查点和有效记忆读取；不开放写文件、命令、MCP、浏览器或计算机操作 |
| `plan` | 在只读范围内允许维护任务计划 |
| `execute` | 使用 daemon 已配置的权限，保留原有审批与能力校验 |

模式只缩小已有权限。切换核对修订和会话所有权，并要求没有活动或待核对 Run。Run 接受时在同一数据库事务保存不可变模式绑定；后续切换不改写原 Run。模式不是操作系统隔离机制。工具列表说明配置与模式限制，实际执行仍受模型路由、已连接执行环境和本次执行计划约束。

## 跟踪任务计划

计划记录步骤、依赖、验收条件和修订，持久状态为 `pending`、`running`、`blocked`、`completed`、`skipped`。有向依赖必须无环；被跳过的前置步骤不算完成。

模型通过 `plan_read`、`plan_update` 维护建议和进度。模型报告与宿主验证分开保存，模型不能伪造宿主验证或用户确认。步骤完成需要相应宿主命令记录，或用户明确选择人工完成；计划不替代实际命令和工具的授权。

TUI 的 `/plan` 和 Desktop 的 Workflow 页面提供查看及操作入口。所有写入带请求 UUID 与预期修订；状态、事件和 Outbox 在同一关系数据库事务中提交。

## 预览、应用和撤销变更

`patch_preview` 将统一 diff 与预期文件修订转换为多文件变更集；`patch_apply` 针对确切变更 ID、修订和内容哈希请求审批。应用前先持久化意图，再核对工作区路径与文件版本并执行写入。

变更仅支持 UTF-8 文本，最多 32 个文件，单文件最多 1 MiB，前后正文与 diff 合计最多 4 MiB。保留已有文件权限；不恢复目录元数据。跨文件写入不是文件系统原子事务。宿主锁只串行化本产品的写入，外部编辑器不共享此锁；版本核对与文件替换之间仍有竞态，不构成操作系统级 CAS。发生部分写入、取消或进程中断时进入 `uncertain`，不得盲目重放。

`checkpoint_read` 查看记录，`checkpoint_undo` 生成反向预览。TUI 使用 `/changes` 查看，`/undo` 请求反向预览；Desktop 在读取具体 diff 后提供人工应用入口。撤销要求当前文件仍匹配原变更的写后版本，随后重新核对并审批反向变更。已完成 Run 的人工撤销使用独立宿主操作，不将旧 Run 改回运行中，也不要求发起新的模型请求。

`validation_record` 只能引用 daemon 实际执行并持久化的命令结果，不能提交模型自称的通过标记。验证关联具体历史变更修订；它不能证明外部编辑器未在命令期间修改文件，也不认证当前整个工作树。结果未知的命令不能作为通过证据。

## 输入图片

TUI 使用 `/attach "/绝对路径/图片.png"` 添加本机会话附件，`/detach 1` 按序号移除。Desktop 使用原生文件选择器添加图片，发送前可移除。选择附件不触发截图或计算机控制。

图片通过 `StartRunWithAttachments` 随新 Run 提交，正文、哈希和 Run 接受状态在同一数据库事务保存。支持 PNG、JPEG、WebP、GIF，最多 8 张，单张 16 MiB、合计 32 MiB，边长不超过 8192 像素且单图不超过 16,777,216 像素。模型还必须明确支持图片。经 Gateway 提交时还受其请求正文限制：默认 256 KiB，可配置上限为 16 MiB，包含 base64 和消息包开销；这可能比附件自身的限额更小。Gateway 模型组只允许将图像请求交给显式声明 `vision` 的候选。

客户端在接受结果确认前保留附件与同一请求 ID；未知结果不自动换新请求重发。附件不能混入当前 Run 的纠偏或跟随输入。图片正文不进入普通事件或调试输出，但会进入 daemon 媒体存储与模型上下文；文本隐私处理不等于图片脱敏，提交前须自行确认图片内容。
