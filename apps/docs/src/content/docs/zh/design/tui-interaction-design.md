## 1. 设计结论

Lyonbrown TUI 以对话和任务为主，减少常驻界面元素，不复制其他产品的品牌元素：

- 单一、可滚动的对话与活动流是默认工作区；
- 输入区（Composer）固定在底部，任务运行时仍可接收用户输入；
- 会话、模型、主题、语言、帮助和活动检查器使用临时浮层（Overlay）；
- 审批嵌入当前任务流，不用脱离上下文的全屏确认页；
- 默认主题为 `hearth-teal`，同时内置六套可持久化主题；
- 首发界面语言为英文和简体中文，命令、模型 ID、路径和快捷键不翻译。

TUI 默认不使用常驻多栏布局。多栏会压缩终端正文、破坏终端原生的滚动历史，并增加 SSH、tmux 和窄终端中的操作成本。详情通过浮层或临时全屏视图访问。

### 1.1 技术选型与视觉参考

Node TUI 精确固定 `@earendil-works/pi-tui@1.0.0`，使用它提供的 `TuiMainScreen`、`Editor`、自动补全、键盘输入、终端文本安全处理、宽度截断和真彩色样式。

`rxjs@7.8.2` 将运行时快照（Runtime Snapshot）转换为 Observable 数据流；`agent-client` 和 `agent-launch` 分别负责认证 gRPC 通信、后台进程（daemon）的发现与启动。

2026-10-06 的本机 PTY 黑盒验收确认：界面先于模型传输出现；连接后进入 `Ready`；模型缺失时只显示 `Required`，必须由用户按 `D` 或 Enter 明确开始下载。

当前快捷键为 `F2` 切换语言、`Ctrl-P` 打开命令面板、`Ctrl-O` 打开活动检查器、`Ctrl-C` 取消或退出。完整场景、证据与尚未通过项见[本机真实场景黑盒验收](/zh/design/tui-black-box-validation/)。

本文下方的 PNG 是产品设计效果图，用于说明交互、信息层级和主题。实机验收记录见上述黑盒验收页；图中的 Rust/Cargo 文本仅为示例，仓库产品实现采用 Node.js / TypeScript。

## 2. 信息架构

默认界面只有四个纵向区域：

```text
Context line        workspace · mode · model
Transcript          user intent · answer · grouped activity
Composer            input · focus · queue
Status line         cancel · details · commands
```

### 2.1 上下文栏

上下文栏（Context line）只显示当前决策需要的信息：

- 工作区；
- 自动选择（`Auto`）或已固定选择的 Worker；
- 本地/远程属性；
- 当前模型。

会话 ID、token、完整路由原因和诊断数据不常驻显示，由活动检查器（Inspector）按需展开。

### 2.2 对话区

对话区（Transcript）显示对话和按执行步骤聚合的活动，不把每个底层事件都显示为聊天消息。活动默认折叠为一行，当前活动可以展开，显示命令和必要输出。

### 2.3 输入区

输入区始终是主要焦点。边框和光标表示焦点位置，主题色只作强调，不依赖颜色区分输入状态。

### 2.4 浮层

浮层临时显示设置或详情，不改变会话，也不清空输入区：

- `/model`：模型与路由策略；
- `/theme`：主题预览与持久化；
- `/language`：英文/简体中文；
- `/sessions`：新建、选择和恢复；
- `/status`：运行时与当前路由摘要；
- `/help`：命令和快捷键；
- `Ctrl-O`：当前活动或审批详情。

命令界面使用同一份固定列表，顺序为：`/model`、`/theme`、`/language`、`/sessions`、`/new`、`/resume`、`/status`、`/queue`、`/help`、`/quit`。

`Ctrl-P` 从对话界面打开可搜索的命令面板。只有输入框为空时，`?` 才打开帮助；`/help` 打开同一个帮助界面。`F2` 全局切换语言，不需要先打开浮层。

`/model`、`/theme`、`/language`、`/status`、`/help` 和 `/quit` 打开对应界面或执行本地操作。`/sessions`、`/new`、`/resume` 显示为不可用。

`/queue` 需要消息参数，因此在命令面板中禁用。用户可以输入 `/queue <消息>` 或按 `Alt-Enter` 排队。未知的斜杠命令由客户端拦截并显示当前语言的提示，绝不会作为普通提示词提交。

模型选择只发送 daemon 公布为可选的路由。daemon 负责保存固定模型或自动选择的设置，并通过状态投影返回客户端。

在模型设置之外，Esc 只关闭最上层浮层或清除选择，不退出 TUI。模型设置是下文明确列出的例外：`Required`、`Failed` 或 `Cancelled` 时 `Esc` 退出；仅当 `allowed_actions` 允许 `Cancel` 时，`Esc` 才取消活跃阶段。

### 2.5 首次模型设置

运行 `agent` 后先进入 TUI，模型传输不会早于界面启动。若 daemon 持有的模型不可用，设置界面展示模型来源、当前阶段、允许动作、失败详情、模型 ID、预估大小，以及适用时的操作 ID。

界面显示 daemon 提供的 `Required`、`WaitingForLock`、`Checking`、`Downloading`、`Verifying`、`Installing`、`Activating`、`Ready`、`Cancelled` 和 `Failed` 阶段，不在客户端虚构额外阶段。

托管模型预设处于 `Required` 时，下载与不下载退出两个选项同样明确：

```text
本地模型  qwen3-1.7b-q4_k_m
根据当前硬件推荐 · 1.03 GiB · 仅在确认后下载

████████████████░░░░░░░░░░░░░░░░  512 MiB / 1.03 GiB  50%

Enter/D  下载     Q/Esc  不下载并退出
```

用户确认后，daemon 执行任务，TUI 保持响应。界面只提供快照 `allowed_actions` 允许的操作：

- `Enter`/`D` 开始下载（Download）；
- 在 `Failed` 或 `Cancelled` 后，`Enter`/`D`/`R` 重试（Retry）；
- 在允许取消的活跃阶段，`C`/`Esc` 使用当前 `operation_id` 取消；
- `Installing` 与 `Activating` 阶段可见，但不可取消。

任一设置阶段都可按 `Q` 退出；`Required`、`Cancelled` 和 `Failed` 还可按 `Esc` 退出，且不会因此发起网络请求。显式配置的路径缺失时，绝不提供 Download 或 Retry。

已知总量时，展示已下载字节、总字节数、百分比和适应宽度的进度条；未知总量时，展示不定进度标记和已下载字节。窄终端逐级压缩同一信息，不隐藏设置状态。

模型设置 RPC 等待响应期间，界面禁用重复操作。没有待处理的模型设置 RPC 时，在允许退出的状态按 `Q` 或 `Esc` 会立即退出。若 `Download`、`Retry` 或 `Cancel` 已经发出，允许的退出请求会等待既有命令的回执，不发送第二条命令。命令失败时保留当前界面，不静默关闭。

快照读取失败和命令失败的提示都会保留，直到设置状态变化。

设置界面支持英文与简体中文，六套内置主题共用一组语义样式值（token）。模型 ID、操作 ID、路径和快捷键不翻译。

过期快照保留展示，供诊断使用。在收到属于已接受服务端代次（server epoch）的新状态前，禁用 `Download`、`Retry`、`Cancel` 等 daemon 操作；本地 `Q` 退出和全局 `F2` 语言切换仍可用。

退出客户端不会取消 daemon 已经接受的下载；取消必须显式发起。校验是独立可见的阶段，运行时绝不加载未经校验的文件。

### 2.6 基于快照的活动检查器

TUI 检查器只读展示最后一次已接受 `RuntimeSnapshot` 中的活动，不发送 daemon 命令，也不重建快照未携带的事件。

只有精确匹配 `Ctrl-O` 的按键组合才从对话界面打开或关闭检查器，并替换其他普通浮层。模型设置与审批的输入优先级更高，出现时会关闭检查器。

列表保留快照顺序，以稳定的 `turn_id + step_id` 定位每一项，不使用显示序号。默认跟随最新执行步骤；选择较早的项目后，后续快照更新仍保持该项目选中。重新选择最新项目则恢复跟随。

若固定选择的目标消失，界面回退到最新项目并重置详情滚动位置。会话或 daemon 代次改变时，关闭检查器并清除旧选择，避免混用不同会话或进程代次的缓存详情。

详情窗格只展示快照中存在的证据：

- 路由与回退原因、阶段、轮次与步骤 ID、上下文计数；
- token 用量，包括缓存读取用量；
- 助手输出、工具参数和状态，以及存在时的审批身份；
- 工具结果、输出、错误、耗时、调用 ID 和步骤结果。

动态文本和 JSON 先经过终端安全清理。字段、JSON 深度、条目数、字符数、集合大小、行数及总字符数均有上限，恶意或超大载荷会被截断。格式化后的详情按状态投影的代次（generation）、选中目标和界面语言缓存，重复渲染不会反复序列化。

标题始终用当前语言标明 `状态已同步` 或 `过期缓存`；断线时仍可读取最后一次已接受的证据。

远端状态投影只接受 daemon 代次匹配、版本号（revision）更新的快照。重复版本或代次不匹配的快照不能局部改变对话、审批或检查器状态。

响应式模式在中英文下保持一致：

- `90×20` 及以上使用左右列表/详情双栏；
- `52×12` 使用上下堆叠窗格；
- `30×8` 一次只显示一个窗格，Enter/Right/Tab 进入详情，Left/Shift-Tab 返回列表。

列表和详情均支持方向键、Page Up/Down 与有界滚动；详情还支持 Home/End。检查器的范围限于快照中的活动，不提供事件时间戳、严格事件历史、历史 `ToolPreview`、能力记录或完整诊断信息。复制使用终端原生选择。

## 3. 核心交互

### 3.1 执行中引导与排队

![执行中引导与排队](/zh/assets/tui/interaction-live-steering.png)

任务运行时，输入区支持立即引导和排队两种输入意图，并提供取消和详情操作：

| 操作        | 语义             | 对运行时的影响                                |
| ----------- | ---------------- | --------------------------------------------- |
| `Enter`     | 立即引导当前轮次 | 形成 `SteerCurrentTurn`，在下一个安全边界注入 |
| `Alt-Enter` | 排队到下一步     | 形成 `QueueFollowUp`，不打断当前工具          |
| `Ctrl-C`    | 取消当前轮次     | 第一次请求取消，第二次强制停止                |
| `Ctrl-O`    | 查看详情         | 打开当前活动检查器，不改变执行                |

排队内容显示在输入区下方，可移除或编辑。界面必须明确写出“立即引导”和“排队到下一步”，不能只靠快捷键提示推断。

终端无法区分 `Alt-Enter` 时，必须提供 `/queue <text>` 等价入口。多行输入使用可配置的 `Ctrl-J`；不能占用引导和排队语义。

### 3.2 内联工具审批

![内联工具审批](/zh/assets/tui/interaction-inline-approval.png)

审批由类型化 `ToolPreview` 驱动，固定呈现：

- 工具与风险等级；
- 完整命令或动作；
- 工作目录与目标；
- 影响范围；
- `host/unsandboxed` 或具体沙箱后端；
- 所需密钥（Secret）的名称，不显示密钥值。

动作顺序和语义固定：

1. 拒绝本次（Deny once，默认焦点）；
2. 允许本次（Allow once）；
3. 在本会话中允许此工具（Allow this tool for session）；
4. 拒绝其余高风险操作（Deny remaining risky actions）。

关闭窗口、客户端断开、超时或无法渲染预览均视为拒绝。

等待审批时，第一次按 `Ctrl-C` 会尝试拒绝本次，随后无论拒绝回执是否失败，都尝试取消当前轮次。取消成功且审批仍在继续时，第二次按 `Ctrl-C` 会发送强制停止（Force stop）并退出客户端。

模型设置与审批优先处理输入。进入这些安全关键状态时，已有的命令面板或帮助浮层会关闭；状态结束后也不会自行恢复。

### 3.3 模型、主题与语言控制面板

![模型、主题与语言控制面板](/zh/assets/tui/interaction-control-palette.png)

控制面板是临时浮层，包含模型（Model）、主题（Theme）和语言（Language）三个分区，均可通过键盘访问：

- 模型变更只从下一个执行步骤生效；
- 会话上下文和工作记忆不因模型变更而重置；
- 主题支持即时预览，`Enter` 应用并记住，Esc 恢复已保存主题；
- 语言切换立即重绘客户端文案，不改变对话原文；
- 当前值、已保存值和正在预览的值必须可区分。

界面语言根据系统语言设置（locale）初始化，可通过全局 `F2`、本地 `/language` 命令和语言浮层切换。模型分区只显示快照中由 daemon 公布为可选的模型。

主题和语言属于客户端偏好，固定会话模型的选择属于共享应用层状态，模型供应商（Provider）凭据和模型安装状态属于运行时与配置状态。这三类状态不得混入同一个无类型的设置映射。

## 4. 输入状态机

| 当前状态                | `Enter`      | `Alt-Enter`            | `Esc`             | `Ctrl-C`                                   |
| ----------------------- | ------------ | ---------------------- | ----------------- | ------------------------------------------ |
| Ready                   | 提交新轮次   | 排队为提交后的后续输入 | 清除选择/关闭浮层 | 清空输入；再次按下退出确认                 |
| Streaming / RunningTool | 立即引导     | 排队下一步             | 关闭浮层          | 取消当前轮次                               |
| AwaitingApproval        | 执行焦点动作 | 无操作                 | 拒绝本次          | 第一次拒绝本次并取消；第二次强制停止并退出 |
| Overlay                 | 应用/进入    | 由浮层定义             | 关闭浮层          | 关闭浮层；再次按下取消当前轮次             |
| Cancelling              | 无操作       | 无操作                 | 无操作            | 强制停止                                   |

所有键盘动作都必须先转成类型化的界面操作意图，再映射到 `AgentCommand`。界面组件不直接操作执行内核（Kernel）。

### 5.2 语义样式值

每套主题至少提供：

```text
background
surface.raised
surface.active
text.primary
text.secondary
text.faint
accent.primary
accent.secondary
status.success
status.warning
status.danger
border.default
focus.ring
```

状态必须同时具有文字或符号。成功、警告、危险不能只通过绿色、黄色、红色表达。

## 6. 多语言规则

- 初始支持 `en-US` 和 `zh-CN`。启动时，系统语言标签为 `zh-CN`、`zh_CN`、`zh-Hans` 等时选择 `zh-CN`；未知或不可用的标签回退到 `en-US`。
- 不附加修饰键的 `F2` 可在模型设置、审批或普通对话界面全局即时切换客户端文案。
- `/language` 切换当前界面语言；`/language en-US` 和 `/language zh-CN` 显式选择语言。这些都是客户端本地命令，不访问 daemon，也不改变对话内容或会话状态。参数无效时，以当前语言显示 `/language [en-US|zh-CN]` 用法。
- 命令面板标题、搜索/空结果/禁用状态、帮助快捷键、命令标签和未知命令反馈均提供中英文版本。模型设置、审批或浮层优先处理输入时，`F2` 仍然可用。
- 语言和主题选择会持久化；偏好文件损坏、过大或写入失败不会阻止 TUI 启动或形成未处理的 Promise 拒绝错误。
- 斜杠命令、配置键、模型 ID、Provider ID、命令、路径和快捷键保持稳定英文形式。
- 标题、状态、帮助、风险说明、动作和空状态全部本地化。
- 对话中已产生的用户与模型内容保持原文；只更新客户端界面文案。
- 中文按 Unicode 字素簇编辑，宽度按终端单元格计算；不假设一个 Unicode 标量值等于一个终端单元格。
- 文案长度不得决定布局正确性；30×8、52×12 和 90+ 列宽均需要中英文快照测试。

## 7. 响应式与可访问性

- `90+` 列：完整对话区、输入区和状态提示；浮层使用受限宽度。
- `52–89` 列：缩短上下文栏，浮层占满可用宽度。
- `30–51` 列：只保留任务、关键状态和单行动作；详情按需全屏。
- `<30` 列或 `<8` 行：显示可恢复的终端过小提示，不能崩溃。
- 焦点不仅用颜色表示；选中行同时使用前导符和文本标签。
- 支持终端原生选择与复制，避免强制使用备用屏幕而破坏滚动历史。
- 动态输出保持稳定锚点，不让输入区随流式 token 输出跳动。

命令面板、帮助与活动检查器在 30×8、52×12、90×20 三档尺寸下均需覆盖中英文渲染。命令面板和帮助在前两档使用全部可用区域，宽屏使用居中的限宽浮层；活动检查器分别使用单窗格、上下堆叠和左右双栏布局。

## 8. 模块边界

模块按以下职责划分：

| 能力                                  | 所属模块                    |
| ------------------------------------- | --------------------------- |
| `Theme`、语义样式值与 Pi TUI 样式映射 | TUI 客户端                  |
| `Locale`、文案目录与键位提示          | TUI 客户端，共享语言 ID     |
| `UiPreferences` 持久化                | 配置/客户端偏好存储         |
| `SteerCurrentTurn`, `QueueFollowUp`   | `agent-app` 类型化命令      |
| `ApprovalView`, `ToolPreview`         | `agent-app` / `agent-tool`  |
| 会话模型固定选择与 `RoutingDecision`  | `agent-app` / `agent-model` |

`UiPreferences` 至少包含：

```text
theme_id
locale
reduced_motion
```

主题未知时回退到 `hearth-teal`；语言未知时回退到系统语言或英文，不得阻止应用启动。

## 9. 验收清单

- 三组基线交互均有英文和简体中文渲染测试；
- 六套主题覆盖 Ready、Running、Approval、Error 和 Overlay 状态；
- 切换主题或语言不重启运行时、不改变会话；
- 切换模型不丢失上下文，只影响下一个执行步骤；
- 引导、排队、取消和强制停止具有互斥且可测试的命令；
- 审批默认拒绝，命令、目录、影响和沙箱状态完整可见；
- 调整终端大小、Unicode/CJK 输入输出、查看滚动历史、复制和长输出均不引发崩溃；
- 所有颜色组合通过对比度检查，状态不依赖颜色单独传达。
