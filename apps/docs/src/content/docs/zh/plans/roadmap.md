## 当前产品状态

`agentd` 持有 Runtime、模型、工具、MCP 连接与 EventStore；TUI 和 Electron Desktop 是认证 gRPC client。当前生产组合已接通 Pi Runtime、本地模型和持久事件。Electron Desktop 已有连接与聊天骨架，完整交互和分发仍待完成。架构与能力边界见[本地 gRPC C/S](/zh/architecture/grpc-client-server/)、[组合根](/zh/architecture/composition-root/)和[Electron Desktop](/zh/architecture/electron-desktop/)。

Windows 开发机已有独立 daemon、真实 GGUF 下载/激活/推理、工具审批、取消和缓存重启记录；macOS arm64 已通过独立 daemon 与可移动开发制品验收。具体记录见 [TUI 黑盒验收](/zh/design/tui-black-box-validation/)和[发布制品](/zh/reference/release-artifacts/)。这些证据尚不能证明三平台日常代码任务可用或正式可发布。

2026-10-14 的 36 条双语探索性决策模型基准中，意图、风险、工具需求准确率分别为 55.6%、38.9%、75.0%；[System One 决策层](/zh/architecture/system-one-decision-layer/)继续固定采用 `continue_pi`。

## 单机可用性缺口（2026-10-16 代码核对）

近期工程优先项是按操作能力推进跨平台升级，覆盖 Windows、macOS、Linux。每项能力先明确共同契约，再复用通用实现并补齐必要的平台适配，分别验证三平台行为。工程约束维护在根目录 `AGENTS.md`。现有 Windows 实现与验证记录作为跨平台基线，2026-10-16 已补齐 POSIX 基础适配，并完成 Mac 独立 daemon 启动验证；三平台完整任务验收仍待完成。

近期按以下标准判断单机 Coding 是否可用：从 TUI 或 Desktop 提交真实仓库任务，Agent 能定位代码、修改文件、运行构建/测试、根据失败继续修复并说明验证结果；多轮交互、取消、重连和重启后的状态必须可理解。聊天和一次文件写入 smoke 不能单独证明达到该标准。

### 跨平台实现检查点（2026-10-16）

- POSIX 使用原生 `openat`、`O_NOFOLLOW`、`flock`、目录句柄及身份复核；Darwin 还检查扩展 ACL。实现覆盖 macOS/Linux x64 与 arm64，其他平台或架构明确拒绝。
- GGUF 和决策模型 bundle 使用私有目录、完整身份键、受控 staging、原子发布及回调前后校验。POSIX advisory lock 约束本适配器的并发操作，不能阻止同一 OS 用户下的恶意进程写入；Windows 原生 share-deny 保持不变。模型 bundle 的历史版本清理仍待补充。
- 文件工具新增有界目录枚举与字面量文本搜索。进程工具使用参数数组、受限继承环境、有界输出和超时/取消清理，必须经高风险审批；它以主机用户权限运行，不是 OS 沙箱。
- 新增 `pnpm smoke:platform`，验证独立 daemon、原生发现、认证 gRPC、SQLite 和无模型下载启动，成功标记为 `PLATFORM_SMOKE_OK <os>-<arch>`。本机已返回 `darwin-arm64`。
- macOS arm64 已通过 frozen install、preflight、format、lint、typecheck、test、build 和 `ci-gate`。该检查点的完整门禁包含原生适配 46 项、agentd 277 项、脚本 79 项通过；平台专属跳过项不计入通过数。Windows/Linux 尚无该检查点的真实运行结果。
- macOS arm64 开发制品通过独立导入、SQLite、平台预编译包与目录搬移 smoke，含空格/中文路径的启动器也已验证。制品与源码硬链接已解除；最终安装分发和真实 GGUF 任务仍待验收。
- 打包与启动器已区分三平台，GGUF/TUI 验收入口不再只允许 Windows，决策模型脚本不再强制 F 盘。CI 已配置三平台质量门禁和独立 daemon smoke；配置存在不等于远端执行通过。

### 跨平台操作升级范围

以下为实施与验收范围，不表示已经完成适配。统一的是操作契约和可观察行为；权限、文件锁、进程终止、终端和签名仍使用各系统适用的机制。

| 能力              | 需要统一的行为                                                   | 平台适配与验收重点                                                                            |
| ----------------- | ---------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| 文件与工作区      | 读写、编辑、目录枚举、搜索、原子替换和工作区访问边界             | 路径分隔符、盘符、大小写、Unicode、符号链接/reparse point、文件身份与访问权限。               |
| 进程与命令        | 参数数组、工作目录、环境、输出、退出结果、取消、超时和子进程清理 | 可执行文件发现、shell 选择与引用规则、进程树终止；避免依赖某个系统命令或 shell 语法。         |
| daemon 与本地安全 | 工作区身份、私有目录、发现、认证、互斥锁和启动/关闭              | Windows ACL 与 POSIX owner/mode、锁与稳定目录句柄提供等价的安全约束。                         |
| 模型与持久存储    | 下载、校验、安装锁、原子激活、缓存、取消和恢复                   | 原生依赖的 OS/架构预编译支持、文件锚定、崩溃清理；分别记录实际验证过的硬件后端。              |
| Git 与客户端      | Git 工作区生命周期、TUI 输入/输出、Desktop 连接与受限 preload    | Git 可执行文件和路径处理、不同终端/PTY 行为、客户端生命周期；桌面交互权限单独声明。           |
| 验证与分发        | 共用能力契约测试、真实任务场景和检查结果格式                     | 为三平台配置运行环境与真实 smoke，逐步替换 Windows 专用验收入口，分别验证制品与安装生命周期。 |

按能力推进顺序为：文件/进程/本地安全 → 模型与存储 → Git 与客户端 → 真实任务与制品。不支持的能力明确返回不可用及原因；原生安全能力缺失时继续拒绝操作。平台支持状态必须标明 OS、架构和运行证据，不能由一个平台的测试推定其他平台可用。

MCP、Secret 和 Skills 的接入按真实任务需要推进；各能力验证前继续 default deny。[System One 决策层](/zh/architecture/system-one-decision-layer/) 保持 `continue_pi`，扩大独立评测集和校准工作可继续，但分类质量暂不作为普通任务执行的前置门槛。

## 后续迭代主线：跨平台操作 → 单机可用 → 分布式 Agent

2026-10-16 已确认将分布式架构纳入后续主线。执行顺序如下，各阶段以验收结果推进，不把方案中的候选模型、传输库或自动恢复能力视为已经确定或实现。

1. **操作能力跨平台与单机真实任务可用。** 按能力完成 Windows、macOS、Linux 的契约、适配和验收，解决上述 P0，再分别完成客户端、模型、工具、上下文和事件恢复的真实任务验证；发布能力按平台单独验收。
2. **任务契约与本地多 Agent。** 区分 Node、Agent、Run、Task 和 Attempt，定义依赖、授权、预算、结果提交与 Root 验收。Root 在本机创建两个独立 Subagent，隔离会话和工作区，并由可替换的本地调度接口执行。Pi 继续留在适配层。
3. **跨节点 Subagent。** 增加持久设备身份、加入与执行授权、安全传输、节点能力、原子接单、租约、取消和断线结果回传，再接入 LAN/VPN 候选发现。单机运行不依赖中心服务。
4. **分布式 Coding，再验证数据采集。** Coding 使用固定基线和独立 Git 工作区，回传 commit、日志与测试证据，由 Root 验收和集成；数据采集复用任务协议验证结构化产物。
5. **状态复制、主动交接与可选 Center。** 保持 Root Session 单写入权，增加增量同步、`ownerEpoch` 和明确的协调权交接；没有相应协议和故障测试前，不承诺自动接管。

每个交付检查点执行仓库规定的 frozen install、preflight、format、lint、typecheck、test、build 和 `ci-gate`，并按变化补充真实场景证据。当前客户端 gRPC 与本地 daemon epoch 继续用于本地边界，不能直接当作节点间协议或 Root 协调权实现。
