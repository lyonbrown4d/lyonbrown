## Integrated on `main`

- Node.js 24, pinned pnpm, strict ESM, repository gates, and bilingual
  VitePress documentation.
- TypeScript domain, protocol/gRPC, authenticated client, launch coordinator,
  durable Runtime adapter, Pi kernel adapter, SQLite EventStore, local control
  plane, Windows native path verification, and local-model foundation.
- The Node TUI replaces the former Rust `apps/agent-cli` implementation and
  pins `@earendil-works/pi-tui@1.0.0`.
- The TUI opens chat by default and includes immediate connection state,
  snapshot revision fencing, English and Simplified Chinese, six themes, a
  responsive model-setup surface aligned with the accepted design, approvals,
  command palette, Activity Inspector, and terminal text safety.
- GUI/Desktop code, root Cargo metadata, Rust crates/providers, Rust build
  scripts, and the final Rust TUI snapshot are removed. The tracked repository
  contains no `.rs`, `Cargo.toml`, or `Cargo.lock` product files.
- Windows native model storage now covers private ACLs, reparse-point and file
  identity checks, install locking, bounded staging, atomic activation, and
  installed-file anchoring. Successful activation also safely removes
  same-model staging left by a crashed process.
- Model downloads use the Node 24 built-in `fetch` to stream into
  same-filesystem staging supplied by native storage. The request and write
  share one cancellation signal, with finitely bounded transient retries before
  response headers arrive.
- Protocol `.proto` schemas and versioned wire fixtures remain tracked contract
  sources. Generated TypeScript/gRPC files are Git-ignored and regenerated by
  package lifecycle hooks before lint, typecheck, test, and build.
- Hand-written TypeScript now uses `@lyonbrown/...` workspace-root aliases.
  Repository tests reject relative module specifiers and cross-workspace access
  to private aliases; production builds rewrite private aliases to directly
  executable Node ESM `.js` paths.
- Authenticated loopback gRPC channels explicitly disable environment HTTP
  proxy discovery, so local daemon traffic cannot be redirected to a proxy.
  Production composition passes only `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`,
  and their lowercase forms to Node 24 `setGlobalProxyFromEnv` for daemon-owned
  external model requests; no other environment variables enter global proxy
  configuration.
- The production launcher and `agentd` composition root are connected. The
  daemon opens the SQLite EventStore, owns the Pi Runtime and local-model
  service, publishes discovery only after authenticated gRPC is ready, and
  tears down owned resources in bounded reverse order.
- The local-model lease now provides bounded streaming chat through
  `node-llama-cpp`. It permits one active inference, uses a fixed 4096-token
  context, propagates cancellation, and bounds request, output, queue, and
  shutdown resources. Qwen3 calls through `node-llama-cpp` set
  `budgets.thoughtTokens=0`, preventing hidden thought from consuming the
  client-visible output budget.
- Model discovery and download remain background operations. The daemon uses a
  pinned trusted catalog plus `node-llama-cpp` RAM/VRAM and GGUF metadata to
  recommend a hardware-compatible model, falling back conservatively to the
  smallest catalog entry when evaluation fails. Download is optional and starts
  only after explicit user action; the TUI projects the recommendation reason,
  setup, progress, cancellation, failure, activation, and activation-retry
  states.
- Client-visible snapshots use a daemon-owned monotonic transport revision, so
  Runtime recovery revisions and model-only updates cannot violate client
  fencing.
- Each user, follow-up, or steering message is bounded to 64 KiB at the daemon
  command boundary, matching the local-model per-message ceiling. The Kernel's
  256 KiB limit is a defensive cap on the constructed inference input, not a
  single-message allowance. Inactive sessions rotate before a new turn at 32
  historical turns or 4 MiB of user text; active-turn follow-ups are bounded to
  eight entries and 512 KiB in aggregate. The daemon serializes budget checks
  and persistence through one FIFO command lane so concurrent RPCs cannot
  bypass those limits.

## Current product state

The repository is Node.js/TypeScript-only. The production C/S path is now
composed from TUI launcher through authenticated gRPC to the daemon-owned
EventStore, Pi Runtime, and local model. This is an implemented and focused-test
checkpoint, not yet release evidence.

The production kernel now has workspace-confined file tools and explicit
approval, while its secret resolver still rejects. MCP is not connected.
GUI, Desktop, and mobile clients remain out of scope. Real-GGUF download,
activation, inference, cancellation, cached restart, and bounded shutdown are
verified only on the current Windows development machine through production
composition. A relocatable development directory is verified, but the archived,
signed, installed final artifact remains unverified, so this is not a
release-readiness claim.

The architecture remains singular: `agentd` owns Runtime, models, tools, MCP,
and EventStore; the TUI is only an authenticated gRPC presentation client. No
embedded Runtime, GUI fallback, or Rust compatibility path may be added.
